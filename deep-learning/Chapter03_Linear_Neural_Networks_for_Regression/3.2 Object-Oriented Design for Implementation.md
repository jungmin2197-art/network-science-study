# 3.2 Object-Oriented Design for Implementation

> 딥러닝 프로젝트를 **모듈화(Modularization)** 하여 코드의 재사용성과 유지보수성을 높이는 설계 방식

---

## 등장 배경

앞 절에서는 **Linear Regression**의 수학적 원리와 학습 과정을 이해하였다. 하지만 실제 딥러닝 프로젝트에서는 단순히 모델 하나만 구현하는 것으로 끝나지 않는다.

프로젝트가 커질수록 다음과 같은 요소들을 함께 관리해야 한다.

- Data
- Model
- Training
- Loss Function
- Optimizer
- Evaluation

이 모든 기능을 하나의 파일이나 클래스에 작성하면 코드가 복잡해지고 유지보수가 어려워진다.

이를 해결하기 위해 D2L에서는 **Object-Oriented Design(객체지향 설계)** 를 사용한다.

객체지향 설계를 통해 각 기능을 독립적인 클래스로 분리하면 **재사용성(Reusability)**, **유지보수성(Maintainability)**, **확장성(Scalability)** 을 크게 향상시킬 수 있다.

---

## 핵심 아이디어

> **하나의 클래스가 모든 일을 하지 않는다. 각 클래스는 하나의 역할만 담당한다.**

D2L에서는 딥러닝 프로젝트를 크게 다음과 같이 구성한다.

| Class | 역할 |
|:------|:-----|
| **Module** | 모델과 Loss Function 정의 |
| **DataModule** | 데이터 생성 및 관리 |
| **Trainer** | 학습(Training Loop) 관리 |

이처럼 역할을 명확하게 분리하면 새로운 모델이나 데이터셋을 추가하더라도 기존 코드를 거의 수정하지 않고 확장할 수 있다.

또한 이러한 구조는 **PyTorch Lightning**과 같은 실제 딥러닝 프레임워크에서도 동일한 철학으로 사용된다.

---

## 주요 개념

### Utilities

객체지향 설계를 보다 편리하게 사용할 수 있도록 여러 Utility 클래스를 제공한다.

대표적으로

- `add_to_class`
- `HyperParameters`
- `ProgressBoard`

등이 있다.

#### 왜 사용하는가?

- 코드의 재사용성을 높일 수 있다.
- 반복되는 코드를 줄일 수 있다.
- Jupyter Notebook 환경에서 코드를 여러 셀로 나누어 작성하기 편리하다.

---

### Module

Module은 **딥러닝 모델을 정의하는 핵심 클래스**이다.

모델 구조(Forward), Loss Function, Optimizer 등 모델 학습에 필요한 기능을 하나의 객체로 관리한다.

#### 왜 사용하는가?

- 모델 관련 기능을 하나의 클래스에서 관리할 수 있다.
- 새로운 모델을 쉽게 상속(Inheritance)하여 구현할 수 있다.
- PyTorch의 `nn.Module`과 동일한 구조를 사용하므로 실제 프로젝트에 적용하기 쉽다.

---

### DataModule

DataModule은 데이터를 관리하는 클래스이다.

데이터 생성부터 전처리, DataLoader 생성까지 모든 데이터 관련 기능을 담당한다.

#### 왜 사용하는가?

- 데이터와 모델의 역할을 명확하게 분리할 수 있다.
- 데이터셋이 변경되어도 모델은 그대로 사용할 수 있다.
- 다양한 데이터셋을 쉽게 교체하여 실험할 수 있다.

---

### Trainer

Trainer는 모델의 학습 과정을 관리하는 클래스이다.

Epoch 반복, Mini-batch 학습, Validation, Optimizer 호출 등 전체 Training Loop를 담당한다.

#### 왜 사용하는가?

- 학습 과정을 표준화할 수 있다.
- 반복되는 학습 코드를 줄일 수 있다.
- 모델만 변경해도 동일한 Trainer를 그대로 사용할 수 있다.

---

## 장점

- 역할별로 클래스를 분리하여 코드의 가독성이 높아진다.
- 코드의 재사용성이 높아진다.
- 유지보수가 쉬워 프로젝트 규모가 커져도 관리하기 편하다.
- 새로운 모델이나 데이터셋을 쉽게 추가할 수 있다.
- 실제 딥러닝 프레임워크(PyTorch Lightning)의 구조를 이해하는 데 도움이 된다.

---

## 한계

- 간단한 예제에서는 오히려 코드가 길어질 수 있다.
- 객체지향 프로그래밍(OOP)에 익숙하지 않다면 구조를 이해하기 어렵다.
- 작은 프로젝트에서는 클래스 분리가 다소 과하게 느껴질 수 있다.
