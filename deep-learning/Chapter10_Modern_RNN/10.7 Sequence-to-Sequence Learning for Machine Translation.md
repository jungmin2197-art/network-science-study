# 10.7 Sequence-to-Sequence Learning for Machine Translation

## 논문

**Sequence to Sequence Learning with Neural Networks**

- Ilya Sutskever
- Oriol Vinyals
- Quoc V. Le

NeurIPS 2014

---

# 왜 Seq2Seq가 등장했는가?

Encoder-Decoder 구조는 입력 문장을 하나의 Context Vector로 압축하고 이를 이용하여 출력 문장을 생성할 수 있었다.

하지만 실제 기계 번역에서는

- 입력과 출력의 길이가 서로 다르고
- 출력 문장을 한 단어씩 생성해야 하며
- 학습과 추론 방식도 서로 다르다.

Seq2Seq(Sequence-to-Sequence)는 이러한 과정을 하나의 학습 프레임워크로 정리한 모델이다.

---

# Sequence-to-Sequence란?

Seq2Seq는

> **하나의 Sequence를 다른 Sequence로 변환하는 모델**이다.

예를 들어

```
English

↓

French
```

또는

```
Question

↓

Answer
```

처럼

입력 Sequence와 출력 Sequence가 서로 다른 문제를 해결한다.

---

# 핵심 아이디어

Seq2Seq의 핵심은

> **Encoder가 입력 문장을 이해하고, Decoder가 이를 바탕으로 새로운 문장을 생성하는 것이다.**

전체 과정은

```text
Input Sentence

↓

Encoder

↓

Context Vector

↓

Decoder

↓

Output Sentence
```

로 이루어진다.

---

# Encoder

Encoder는 입력 문장을 순차적으로 읽는다.

예를 들어

```
I

love

AI
```

를 입력하면

마지막 Hidden State를

Context Vector로 사용한다.

```text
I

↓

love

↓

AI

↓

Context Vector
```

---

# Decoder

Decoder는

Context Vector를 초기 Hidden State로 사용한다.

그리고

한 단어씩 출력 문장을 생성한다.

예를 들어

```text
<bos>

↓

나는

↓

AI를

↓

좋아한다

↓

<eos>
```

처럼

문장이 끝날 때까지 반복한다.

---

# Teacher Forcing

학습 과정에서는

모델이 예측한 단어를 사용하는 대신

**실제 정답 단어(Ground Truth)** 를 다음 입력으로 사용한다.

예를 들어

정답 문장이

```
나는 AI를 좋아한다
```

라면

학습 과정은

```text
<bos>

↓

나는

↓

AI를

↓

좋아한다
```

처럼

실제 정답을 계속 입력한다.

이를

**Teacher Forcing**이라고 한다.

---

# 왜 Teacher Forcing을 사용할까?

만약

모델의 예측을 다음 입력으로 사용하면

첫 번째 예측이 틀렸을 때

그 이후의 예측도 계속 틀릴 가능성이 커진다.

예를 들어

```text
<bos>

↓

나는

↓

학교를 (오답)

↓

먹었다 (오답)

↓

...
```

처럼

오차가 계속 누적된다.

Teacher Forcing은

항상 정답을 입력하기 때문에

학습을 더욱 안정적으로 수행할 수 있다.

---

# Loss Function with Masking

문장의 길이는 서로 다르다.

예를 들어

```text
I love AI

↓

나는 AI를 좋아한다
```

와

```text
Thank you

↓

감사합니다
```

는

길이가 다르다.

Batch 학습을 위해

Padding을 추가하지만

Padding은 실제 단어가 아니다.

따라서

Loss를 계산할 때

Padding 부분은 제외해야 한다.

이를

**Masking**이라고 한다.

---

# Training

학습 과정은

```text
Input Sentence

↓

Encoder

↓

Context Vector

↓

Decoder

↓

Prediction

↓

Loss

↓

Backpropagation
```

순으로 진행된다.

Encoder와 Decoder를

동시에 학습한다.

---

# Prediction

추론(Inference)에서는

정답을 사용할 수 없다.

따라서

Decoder가

직접 예측한 단어를

다음 입력으로 사용한다.

예를 들어

```text
<bos>

↓

나는

↓

AI를

↓

좋아한다

↓

<eos>
```

처럼

문장이 종료될 때까지

반복 생성한다.

---

# Evaluation

기계 번역에서는

단순 Accuracy보다

생성된 문장의 품질을 평가하는 것이 중요하다.

대표적인 평가 방법은

**BLEU(Bilingual Evaluation Understudy)** 이다.

BLEU Score는

생성된 문장이

정답 문장과 얼마나 유사한지를 측정한다.

BLEU가 높을수록

좋은 번역 모델이다.

# Seq2Seq 전체 과정

```text
Input Sentence

↓

Encoder

↓

Context Vector

↓

Decoder

↓

Output Sentence

↓

Loss

↓

Backpropagation
```

---

# 장점

- 입력과 출력 길이가 달라도 처리 가능
- 다양한 Sequence 변환 문제 해결
- 기계 번역에 효과적
- 문장 생성 가능

---

# 한계

모든 정보를 하나의 Context Vector에 저장해야 한다.

문장이 길어질수록

- 정보 손실
- 번역 성능 저하
- Long Sequence 처리 어려움

문제가 발생한다.

이를 해결하기 위해

**Attention Mechanism**이 등장하였다.

---

# 후속 연구에 미친 영향

Seq2Seq는 현대 자연어 생성 모델의 출발점이 되었다.

이후

- Attention
- Transformer
- BART
- T5
- GPT

등 대부분의 생성 모델이 Seq2Seq 개념을 기반으로 발전하였다.

특히 Transformer는 Encoder-Decoder 구조를 유지하면서 Attention을 중심으로 모델을 재설계하였다.

---

# 내가 이해한 내용

Seq2Seq는 입력 Sequence를 출력 Sequence로 변환하는 모델이다.

Encoder는 입력 문장을 하나의 Context Vector로 표현하고, Decoder는 이를 이용하여 새로운 문장을 생성한다.

학습에서는 Teacher Forcing을 사용하여 정답 단어를 다음 입력으로 제공하고, Padding 부분은 Masking을 통해 Loss 계산에서 제외한다.

추론에서는 이전에 생성한 단어를 다음 입력으로 사용하며 문장을 순차적으로 생성한다.

Seq2Seq는 기계 번역의 기반이 되었지만, 긴 문장을 하나의 Context Vector에 압축해야 하는 한계가 있었고, 이를 해결하기 위해 이후 Attention Mechanism이 제안되었다.
