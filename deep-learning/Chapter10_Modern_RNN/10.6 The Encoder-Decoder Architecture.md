# 10.6 The Encoder-Decoder Architecture

## 논문

**Learning Phrase Representations using RNN Encoder–Decoder for Statistical Machine Translation**

- Kyunghyun Cho
- Bart van Merriënboer
- Çaglar Gülçehre
- Yoshua Bengio et al.

EMNLP 2014

---

# 왜 Encoder-Decoder가 등장했는가?

기본 RNN은 입력 Sequence를 따라 다음 단어를 예측하는 데에는 적합하지만, **입력 Sequence와 출력 Sequence의 길이가 서로 다른 문제**를 해결하기 어렵다.

예를 들어 기계 번역에서는

```
English

↓

Korean
```

처럼 입력 문장과 출력 문장의 길이가 서로 다를 수 있다.

또한 입력 문장을 모두 읽은 후 새로운 문장을 생성해야 하는 작업도 기존 RNN으로는 처리하기 어렵다.

Encoder-Decoder는 이러한 문제를 해결하기 위해 **입력 Sequence를 하나의 의미 표현(Context Vector)으로 변환한 뒤, 이를 이용하여 새로운 Sequence를 생성하는 구조**를 제안하였다.

---

# 기존 RNN의 한계

기본 RNN은

```text
Input

↓

Output
```

형태의 Sequence Prediction에 적합하다.

하지만

```
Input

↓

새로운 문장 생성
```

과 같이

입력과 출력이 서로 다른 Sequence인 문제에는 한계가 있다.

대표적인 예는

- 기계 번역
- 문장 요약
- 질의응답

등이다.

---

# 핵심 아이디어

Encoder-Decoder의 핵심은 다음과 같다.

> **입력 문장을 하나의 의미 벡터(Context Vector)로 인코딩한 뒤, 그 의미를 바탕으로 새로운 문장을 생성하자.**

즉,

```
Input Sentence

↓

Encoder

↓

Context Vector

↓

Decoder

↓

Output Sentence
```

라는 두 단계로 문제를 해결한다.

---

# Encoder

Encoder는 입력 Sequence를 읽으며 문장의 의미를 하나의 벡터로 압축한다.

예를 들어

```
I

love

AI
```

라는 문장이 입력되면

Encoder는 각 단어를 순차적으로 처리한 뒤 마지막 Hidden State를 Context Vector로 사용한다.

```text
I

↓

love

↓

AI

↓

Context Vector
```

즉,

**입력 문장의 정보를 하나의 고정된 벡터로 표현하는 역할**을 한다.

---

# Context Vector

Context Vector는

입력 문장의 의미를 압축한 벡터이다.

Encoder가 생성한 마지막 Hidden State를 Decoder에게 전달한다.

```text
Encoder

↓

Context Vector

↓

Decoder
```

즉,

Encoder와 Decoder를 연결하는 다리 역할을 한다.

---

# Decoder

Decoder는 Context Vector를 초기 정보로 사용하여 출력 문장을 한 단어씩 생성한다.

예를 들어

```
Context Vector

↓

나는

↓

AI를

↓

좋아한다
```

처럼 이전에 생성한 단어를 이용하여 다음 단어를 계속 예측한다.

---

# Encoder-Decoder 전체 구조

```text
Input Sentence

↓

Encoder

↓

Context Vector

↓

Decoder

↓

Output Sentence
```

Encoder는 입력을 이해하고,

Decoder는 새로운 Sequence를 생성한다.

---

# 문장 생성 과정

예를 들어

```
Input

I love AI
```

를 번역하면

```text
Encoder

↓

Context Vector

↓

<bos>

↓

나는

↓

AI를

↓

좋아한다

↓

<eos>
```

처럼 출력이 생성된다.

여기서

- `<bos>` : Beginning Of Sentence
- `<eos>` : End Of Sentence

를 의미한다.

---

# Encoder와 Decoder의 역할

| Encoder | Decoder |
|----------|----------|
| 입력 문장을 읽음 | 출력 문장을 생성 |
| Context Vector 생성 | Context Vector 활용 |
| 문장의 의미 압축 | 단어를 순차적으로 예측 |

---

# 장점

- 입력과 출력 길이가 달라도 처리 가능
- 다양한 Sequence 변환 문제 해결 가능
- 기계 번역의 기본 구조 제시
- Seq2Seq 모델의 기반

---

# 한계

Encoder는 입력 문장의 모든 정보를 **하나의 Context Vector**에 저장해야 한다.

따라서 문장이 길어질수록

- 정보 손실
- 중요한 단어를 잊어버림
- 번역 성능 저하

가 발생한다.

이를 **Information Bottleneck** 문제라고 한다.

---

# 후속 연구에 미친 영향

Encoder-Decoder 구조는 이후 Sequence Modeling의 표준 구조가 되었다.

특히 다음 모델들의 기반이 되었다.

- Seq2Seq
- Attention
- Transformer
- BART
- T5

Attention은 Context Vector 하나만 사용하는 한계를 해결하였고,

Transformer는 Encoder와 Decoder 구조를 유지하면서 RNN을 Self-Attention으로 대체하였다.

---

# 내가 이해한 내용

Encoder-Decoder는 **입력 문장을 이해하는 과정과 출력 문장을 생성하는 과정을 분리한 모델**이다.

Encoder는 입력 Sequence를 하나의 Context Vector로 압축하고, Decoder는 이를 이용하여 새로운 Sequence를 생성한다.

기존 RNN은 입력과 출력의 길이가 다른 문제를 해결하기 어려웠지만, Encoder-Decoder는 이러한 문제를 해결하여 기계 번역과 같은 Sequence-to-Sequence 문제를 효과적으로 처리할 수 있게 만들었다.

다만 모든 정보를 하나의 Context Vector에 저장해야 하는 Information Bottleneck 문제가 존재하며, 이는 이후 Attention Mechanism이 등장하는 중요한 계기가 되었다.
