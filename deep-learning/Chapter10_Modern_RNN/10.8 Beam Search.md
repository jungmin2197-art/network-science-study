# 10.8 Beam Search

---

# 왜 Beam Search가 필요한가?

Seq2Seq 모델은 Decoder가 한 단어씩 문장을 생성한다.

하지만 매 순간 가장 확률이 높은 단어만 선택하면 전체적으로는 더 좋은 문장을 놓칠 수 있다.

예를 들어

```
I love

↓

AI (0.45)

Machine (0.40)

Deep (0.15)
```

라고 하자.

Greedy Search는

```
AI
```

만 선택한다.

하지만

```
Machine Learning
```

이라는 문장이

최종 확률이 더 높을 수도 있다.

Beam Search는 이러한 문제를 해결하기 위해 **여러 개의 후보 문장을 동시에 유지하면서 가장 좋은 문장을 탐색하는 방법**이다.

---

# Decoder에서 문장 생성

Decoder는

한 번에 한 단어씩 출력한다.

```
<bos>

↓

나는

↓

AI를

↓

좋아한다

↓

<eos>
```

각 단계마다

Vocabulary 전체에 대한 확률을 계산한다.

---

# Greedy Search

가장 단순한 방법은

매 단계마다

가장 높은 확률의 단어 하나만 선택하는 것이다.

예를 들어

```
love

↓

AI      0.45

Machine 0.40

Deep    0.15
```

이면

```
AI
```

를 바로 선택한다.

이를

**Greedy Search**라고 한다.

---

# Greedy Search의 문제점

Greedy Search는

현재 가장 좋은 선택만 고려한다.

예를 들어

```
Start

↓

A (0.6)

↓

End (0.2)
```

최종 확률은

```
0.6 × 0.2 = 0.12
```

이다.

반면

```
Start

↓

B (0.4)

↓

End (0.9)
```

의 최종 확률은

```
0.4 × 0.9 = 0.36
```

이다.

즉,

처음에는 B가 낮은 확률이었지만

전체 문장으로는 더 좋은 결과가 된다.

Greedy Search는 이러한 경우를 찾을 수 없다.

---

# Exhaustive Search

가장 정확한 방법은

가능한 모든 문장을 탐색하는 것이다.

예를 들어

Vocabulary가

```
10,000개
```

이고

문장 길이가

```
20
```

이라면

가능한 경우의 수는

```
10000^20
```

개가 된다.

실제로는 계산이 거의 불가능하다.

---

# Beam Search

Beam Search는

Greedy Search와 Exhaustive Search의 절충안이다.

핵심 아이디어는

> **확률이 높은 후보 문장을 여러 개 유지하면서 탐색하자.**

이다.

---

# Beam Width

Beam Search는

Beam Width(k)를 사용한다.

예를 들어

```
k = 3
```

이라면

항상

상위 3개의 후보 문장을 유지한다.

```
Start

↓

A

B

C
```

를 동시에 탐색한다.

---

# Beam Search 과정

예를 들어

첫 번째 단계에서

```
A 0.5

B 0.3

C 0.2
```

라면

Beam Width가

```
k = 2
```

일 경우

```
A

B
```

만 남긴다.

다음 단계에서는

A와 B에서

새로운 후보를 생성한다.

```
A1

A2

B1

B2
```

전체 후보 중

확률이 높은 두 개만 다시 선택한다.

이 과정을

문장이 끝날 때까지 반복한다.

---

# Beam Search 과정

```text
Start

↓

Top-k 후보 선택

↓

후보 확장

↓

Top-k 후보 유지

↓

반복

↓

최종 문장 선택
```

---

# Beam Width의 영향

### k = 1

```
Greedy Search
```

와 동일하다.

---

### k 증가

더 많은 후보를 탐색한다.

```
Beam Width

↓

성능 ↑

계산량 ↑
```

즉,

k가 클수록

더 좋은 문장을 찾을 가능성은 높지만

연산량도 증가한다.

---

# Greedy Search와 Beam Search 비교

| Greedy Search | Beam Search |
|---------------|-------------|
| 후보 1개 유지 | 후보 k개 유지 |
| 매우 빠름 | 비교적 느림 |
| 지역 최적해 선택 | 더 좋은 전역 해 탐색 |
| 구현 단순 | 구현 복잡 |

---

# Beam Search의 장점

- 더 자연스러운 문장 생성
- Greedy Search보다 높은 성능
- 계산량이 Exhaustive Search보다 훨씬 적음
- 대부분의 Seq2Seq 모델에서 사용

---

# 한계

- Beam Width가 커질수록 계산량 증가
- 항상 최적의 문장을 찾는 것은 아님
- Beam Width를 적절하게 선택해야 함

---

# 후속 연구에 미친 영향

Beam Search는 Sequence Generation 분야의 대표적인 Decoding 알고리즘이 되었다.

현재도

- Seq2Seq
- Transformer
- BART
- T5

등 대부분의 생성 모델에서 사용된다.

다만 GPT와 같은 대규모 언어 모델에서는 Beam Search뿐 아니라

- Top-k Sampling
- Top-p (Nucleus) Sampling
- Temperature Sampling

등 다양한 생성 기법도 함께 사용된다.

---

# 내가 이해한 내용

Beam Search는 새로운 신경망 구조가 아니라 **문장을 생성하는 탐색(Decoding) 알고리즘**이다.

Greedy Search처럼 현재 가장 높은 확률의 단어만 선택하는 것이 아니라 여러 개의 후보 문장을 동시에 유지하면서 탐색하기 때문에 더 자연스러운 문장을 생성할 가능성이 높다.

즉, Beam Search의 핵심은 **현재의 최선이 아니라 전체 문장 확률을 고려하여 가장 좋은 후보를 선택하는 것**이다.
