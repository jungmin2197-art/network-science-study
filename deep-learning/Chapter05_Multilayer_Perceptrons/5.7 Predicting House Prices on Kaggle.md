# 5.7 Predicting House Prices on Kaggle

> **핵심 키워드:** Kaggle · Data Preprocessing · Error Measure · K-Fold Cross Validation · Model Selection · House Price Prediction

---

## 등장 배경

앞 절까지는 딥러닝 모델의 구조와 학습 원리, 그리고 일반화 성능을 향상시키는 다양한 기법을 학습하였다.

하지만 실제 머신러닝 프로젝트에서는 모델을 구현하는 것만으로는 충분하지 않다. 데이터를 수집하고, 전처리하며, 적절한 평가 방법을 선택하고, 가장 성능이 좋은 모델을 선택하는 과정까지 모두 포함되어야 한다.

이번 절에서는 **Kaggle House Prices** 데이터를 이용하여 실제 머신러닝 프로젝트의 전체 과정을 경험한다.

---

## 핵심 아이디어

> **실제 데이터를 전처리하고, 모델을 학습 및 검증한 뒤, 가장 성능이 좋은 모델을 선택하여 Kaggle에 제출한다.**

전체 과정은 다음과 같다.

```
Download Dataset
        │
        ▼
Data Preprocessing
        │
        ▼
Train Model
        │
        ▼
K-Fold Cross Validation
        │
        ▼
Model Selection
        │
        ▼
Prediction
        │
        ▼
Submit to Kaggle
```

즉, 딥러닝 모델을 만드는 것뿐 아니라 **데이터 처리부터 성능 평가까지 전체 파이프라인**을 학습하는 것이 목표이다.

---

## 주요 개념

### 1. Downloading Data

먼저 Kaggle에서 House Prices 데이터를 다운로드한다.

데이터는 크게

- Training Dataset
- Test Dataset

으로 구성되어 있으며,

Training 데이터에는 정답(Label)이 포함되어 있지만,

Test 데이터에는 정답이 존재하지 않는다.

#### 왜 사용하는가?

- 실제 머신러닝 프로젝트와 동일한 환경을 경험하기 위해
- 학습 데이터와 예측 데이터를 분리하기 위해

---

### 2. Kaggle

Kaggle은 머신러닝 및 딥러닝 경진대회를 제공하는 대표적인 플랫폼이다.

연구자와 개발자는 다양한 데이터셋을 이용하여 모델을 학습하고 성능을 비교할 수 있다.

#### 왜 사용하는가?

- 실제 문제를 해결하는 경험을 얻을 수 있다.
- 다양한 공개 데이터셋을 활용할 수 있다.
- 모델의 성능을 다른 사람들과 비교할 수 있다.

---

### 3. Data Preprocessing

실제 데이터는 바로 학습에 사용할 수 없는 경우가 많다.

따라서 다음과 같은 전처리가 필요하다.

- 결측치(Missing Value) 처리
- 범주형 데이터 인코딩
- 수치형 데이터 정규화
- 불필요한 Feature 제거

#### 왜 사용하는가?

- 데이터 품질을 향상시키기 위해
- 모델의 학습을 안정적으로 만들기 위해
- 일반화 성능을 높이기 위해

---

### 4. Error Measure

House Price Prediction은 회귀 문제이므로 Accuracy가 아닌 **오차(Error)** 를 이용하여 모델의 성능을 평가한다.

D2L에서는 **Root Mean Squared Log Error(RMSLE)** 를 사용한다.

RMSLE는 실제 가격과 예측 가격의 로그 차이를 측정하므로, 고가와 저가 주택 모두를 균형 있게 평가할 수 있다.

#### 왜 사용하는가?

- 가격의 절대적인 차이보다 상대적인 오차를 평가할 수 있다.
- 큰 가격 차이에 의한 영향을 줄일 수 있다.
- Kaggle House Prices 대회의 공식 평가 지표이다.

---

### 5. K-Fold Cross Validation

K-Fold Cross Validation은 데이터를 여러 개의 Fold로 나누어 반복적으로 학습과 검증을 수행하는 방법이다.

예를 들어 5-Fold를 사용하면

```
Fold1 → Validation

Fold2 → Validation

Fold3 → Validation

Fold4 → Validation

Fold5 → Validation
```

을 반복하여 평균 성능을 계산한다.

#### 왜 사용하는가?

- Validation 결과의 신뢰성을 높일 수 있다.
- 데이터가 적은 경우에도 효율적으로 활용할 수 있다.
- 특정 Validation Set에 의존하는 문제를 줄일 수 있다.

---

### 6. Model Selection

여러 모델이나 Hyperparameter를 비교하여 가장 좋은 성능을 보이는 모델을 선택하는 과정이다.

예를 들어

- Learning Rate
- Batch Size
- Hidden Layer 개수
- Weight Decay

등을 변경하면서 성능을 비교한다.

#### 왜 사용하는가?

- 가장 일반화 성능이 좋은 모델을 선택하기 위해
- Overfitting을 방지하기 위해
- 최적의 Hyperparameter를 찾기 위해

---

### 7. Submitting Predictions

최종 모델을 이용하여 Test Dataset의 결과를 예측한 후,

예측값을 Kaggle 제출 형식(CSV)으로 저장하여 제출한다.

Kaggle에서는 제출한 결과를 이용하여 Leaderboard 점수를 계산한다.

#### 왜 중요한가?

- 실제 서비스 환경과 동일한 평가 과정을 경험할 수 있다.
- 모델의 일반화 성능을 객관적으로 확인할 수 있다.

---

## 장점

- 실제 머신러닝 프로젝트의 전체 과정을 경험할 수 있다.
- 데이터 전처리의 중요성을 이해할 수 있다.
- K-Fold Cross Validation을 이용한 안정적인 성능 평가가 가능하다.
- Hyperparameter를 비교하며 최적의 모델을 선택할 수 있다.
- Kaggle을 통해 실제 데이터 기반 문제 해결 능력을 기를 수 있다.

---

## 한계

- 높은 성능을 얻기 위해서는 Feature Engineering이 추가로 필요할 수 있다.
- K-Fold Cross Validation은 반복 학습이 필요하므로 시간이 오래 걸릴 수 있다.
- Kaggle 점수가 실제 서비스 성능을 항상 보장하는 것은 아니다.
- 특정 데이터셋에 맞춘 모델은 다른 데이터에서 성능이 떨어질 수 있다.
