# 8.4 Multi-Branch Networks (GoogLeNet)

## 논문

**Going Deeper with Convolutions (GoogLeNet)**

- Christian Szegedy et al.

CVPR 2015

---

# 왜 등장했는가?

VGG는 작은 3×3 Convolution을 반복하여 매우 높은 성능을 달성하였지만, Layer가 깊어질수록 계산량과 Parameter 수가 크게 증가하는 문제가 있었다.

특히 Fully Connected Layer와 많은 Convolution 연산으로 인해 메모리 사용량과 연산 비용이 매우 컸다.

GoogLeNet은 이러한 문제를 해결하기 위해 **높은 성능을 유지하면서도 계산량과 Parameter를 크게 줄이는 새로운 CNN 구조**를 제안하였다.

---

# 기존 CNN의 한계

AlexNet과 VGG는 다음과 같은 문제를 가지고 있었다.

- Layer가 깊어질수록 계산량 증가
- Parameter 수 증가
- GPU 메모리 사용량 증가
- 어떤 Kernel 크기가 가장 좋은지 알기 어려움

GoogLeNet은 다양한 크기의 Convolution을 동시에 수행하여 이러한 문제를 해결하였다.

---

# 핵심 아이디어

GoogLeNet의 핵심은 **Inception Module**이다.

> **한 가지 Convolution만 사용하는 것이 아니라 여러 크기의 Convolution을 동시에 수행하여 다양한 특징을 학습하자.**

즉,

- 1×1 Convolution
- 3×3 Convolution
- 5×5 Convolution
- Max Pooling

을 동시에 수행한 후 결과를 하나로 합친다.

---

# Inception Module

기존 CNN은

```text
Input

↓

3×3 Conv

↓

Output
```

처럼 하나의 Kernel만 사용하였다.

GoogLeNet은

```text
                 Input
                    │
    ┌────────┬────────┬────────┬────────┐
    │        │        │        │
 1×1 Conv 3×3 Conv 5×5 Conv Max Pool
    │        │        │        │
    └────────┴────────┴────────┘
                │
          Concatenate
                │
             Output
```

처럼 여러 Branch를 동시에 수행한다.

이를 **Multi-Branch Network**라고 한다.

---

# 왜 여러 개의 Kernel을 사용할까?

이미지마다 필요한 Feature의 크기가 다르기 때문이다.

예를 들어

- 1×1 → Channel 정보 학습
- 3×3 → 작은 특징 추출
- 5×5 → 큰 특징 추출
- Pooling → 중요한 정보 유지

즉 하나의 Kernel만 사용하는 것보다 다양한 정보를 동시에 학습할 수 있다.

---

# 1×1 Convolution의 역할

GoogLeNet에서는 대부분의 큰 Convolution 앞에 **1×1 Convolution**을 배치한다.

```text
Input

↓

1×1 Conv

↓

3×3 Conv
```

또는

```text
Input

↓

1×1 Conv

↓

5×5 Conv
```

이렇게 사용하는 이유는

**Channel 수를 먼저 줄인 뒤 큰 Convolution을 수행하기 위해서**이다.

이를 **Dimension Reduction**이라고 한다.

---

# Dimension Reduction

예를 들어

입력이

```text
28 × 28 × 256
```

이라고 하자.

바로 5×5 Convolution을 수행하면

계산량이 매우 크다.

대신

```text
28×28×256

↓

1×1 Conv

↓

28×28×64

↓

5×5 Conv
```

를 수행하면

Parameter와 연산량이 크게 감소한다.

즉,

**1×1 Convolution은 계산량을 줄이는 병목(Bottleneck) 역할**을 한다.

---

# GoogLeNet 구조

대표적인 GoogLeNet은 다음과 같이 구성된다.

```text
Input

↓

Convolution

↓

Pooling

↓

Inception Module

↓

Inception Module

↓

...

↓

Global Average Pooling

↓

Softmax
```

총 9개의 Inception Module을 사용하여 매우 깊은 네트워크를 구성하였다.

---

# Auxiliary Classifier

GoogLeNet은 학습 중 Gradient Vanishing을 완화하기 위해 **Auxiliary Classifier**를 추가하였다.

중간 Layer에서도 Classification Loss를 계산하여

- Gradient 전달 개선
- 학습 안정화

효과를 얻었다.

학습이 끝난 후에는 Auxiliary Classifier를 제거하고 메인 출력만 사용한다.

---

# 장점

- 계산량 감소
- Parameter 감소
- 다양한 Scale의 Feature 학습
- 높은 정확도
- Multi-Branch 구조 제안

---

# 한계

- 구조가 복잡하다.
- 구현이 어렵다.
- Branch가 많아 설계가 까다롭다.

이후 ResNet은 더 단순한 구조로 더 높은 성능을 달성하였다.

---

# AlexNet, VGG와 비교

| Model | 핵심 아이디어 |
|--------|--------------|
| AlexNet | Deep CNN의 시작 |
| VGG | 작은 3×3 Kernel 반복 |
| GoogLeNet | Inception Module과 Multi-Branch 구조 |

---

# 후속 연구에 미친 영향

GoogLeNet은 CNN에서 **Multi-Branch Architecture**를 처음으로 성공시킨 모델이다.

또한

- Inception V2
- Inception V3
- Inception V4
- Xception

등 다양한 Inception 계열 모델의 기반이 되었다.

1×1 Convolution을 이용한 Dimension Reduction 역시 이후 ResNet의 Bottleneck 구조 등 다양한 CNN에서 널리 사용되었다.

---

# 내가 이해한 내용

GoogLeNet은 단순히 Layer를 깊게 쌓는 것이 아니라 **여러 크기의 Convolution을 동시에 수행하여 다양한 특징을 학습하고, 1×1 Convolution으로 계산량을 줄인 모델**이라고 이해할 수 있다.

특히 Inception Module은 서로 다른 크기의 Feature를 동시에 추출할 수 있도록 설계되었으며, 1×1 Convolution을 이용한 Dimension Reduction 덕분에 높은 성능과 계산 효율을 동시에 달성하였다.
