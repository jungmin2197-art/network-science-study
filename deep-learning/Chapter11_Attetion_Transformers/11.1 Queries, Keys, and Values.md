# 11.1 Queries, Keys, and Values

---

# 왜 Query, Key, Value가 필요한가?

기존 Seq2Seq 모델에서는 Decoder가 입력 문장의 모든 정보를 하나의 Context Vector에 의존하였다.

문장이 길어질수록 중요한 정보를 잃어버리는 **Information Bottleneck** 문제가 발생하였다.

Attention Mechanism은 필요한 순간마다 입력 문장의 중요한 부분만 선택적으로 참고하도록 하였고, 이를 위해 **Query(Query), Key(Key), Value(Value)** 라는 세 가지 개념을 도입하였다.

---

# 핵심 아이디어

Attention의 핵심은 매우 단순하다.

> **"내가 원하는 정보(Query)와 가장 잘 맞는 정보(Key)를 찾아 그 정보(Value)를 가져오자."**

즉,

```
질문(Query)

↓

비슷한 Key 찾기

↓

해당 Value 가져오기
```

라는 과정이다.

---

# Query (Q)

Query는

> **현재 내가 찾고 싶은 정보**를 의미한다.

예를 들어

```
나는 지금 무엇이 필요한가?
```

라는 질문이라고 생각하면 된다.

번역에서는

현재 Decoder가 생성하려는 단어가 Query가 된다.

---

# Key (K)

Key는

> **각 정보가 가지고 있는 특징 또는 검색용 주소**이다.

모든 입력 Token은

각자 하나의 Key를 가진다.

Query와 Key의 유사도를 계산하여

어떤 정보를 참고할지 결정한다.

---

# Value (V)

Value는

실제로 가져올 정보이다.

즉,

Key는

```
찾기 위한 정보
```

이고,

Value는

```
실제로 사용할 정보
```

이다.

---

# 도서관 비유

Attention은

도서관에서 책을 찾는 과정과 매우 비슷하다.

```
Query

↓

"딥러닝 책을 찾고 싶다."

↓

Key

↓

책 제목 검색

↓

Value

↓

실제 책 내용
```

즉,

- Query → 찾고 싶은 내용
- Key → 검색용 정보
- Value → 실제 내용

이다.

---

# 번역 예시

예를 들어

```
Input

I love AI
```

를

번역한다고 하자.

Decoder가

```
AI를
```

생성하려는 순간

Query는

```
AI와 관련된 정보를 찾고 싶다.
```

가 된다.

Encoder의 각 단어는

```
I

love

AI
```

각각 Key와 Value를 가진다.

Query는

AI의 Key와 가장 높은 유사도를 가지므로

AI의 Value를 가장 많이 가져오게 된다.

---

# Attention 과정

Attention은 다음 순서로 동작한다.

```text
Query 생성

↓

Key와 유사도 계산

↓

Attention Score 계산

↓

Softmax

↓

Attention Weight

↓

Value의 가중합

↓

Output
```

---

# Query와 Key의 관계

Query는

모든 Key와 비교된다.

예를 들어

```
Query

↓

Key1

Key2

Key3
```

각 Key와의

유사도를 계산한다.

가장 비슷한 Key일수록

높은 Attention Weight를 가진다.

---

# Attention Output

최종 출력은

Value들의 가중합이다.

$$
\text{Output}
=
\sum_i
\alpha_iV_i
$$

여기서

- \(V_i\) : Value
- \(\alpha_i\) : Attention Weight

이다.

즉,

중요한 Value일수록

더 크게 반영된다.

---

# Query, Key, Value의 역할

| 구성 요소 | 역할 |
|-----------|------|
| Query | 현재 필요한 정보 |
| Key | 어떤 정보를 찾기 위한 기준 |
| Value | 실제 가져오는 정보 |

---

# 장점

- 필요한 정보만 선택 가능
- 긴 문장에서도 중요한 정보 유지
- Information Bottleneck 완화
- 다양한 길이의 Sequence 처리 가능

---

# 한계

Query, Key, Value만으로는 Attention이 완성되지 않는다.

Query와 Key의 유사도를 어떻게 계산할 것인지가 중요하다.

이를 해결하기 위해 다음 절에서 **Attention Pooling**과 **Attention Score Function**을 학습한다.

---

# 후속 연구에 미친 영향

Query, Key, Value는 현대 Transformer의 핵심 구성 요소이다.

이후

- Bahdanau Attention
- Multi-Head Attention
- Self-Attention
- Transformer
- Vision Transformer
- GPT
- BERT

모두 동일한 Q-K-V 구조를 기반으로 동작한다.

---

# 내가 이해한 내용

Attention은 필요한 정보를 모두 기억하는 것이 아니라 **현재 필요한 정보만 선택적으로 가져오는 메커니즘**이다.

이를 위해 Query는 현재 필요한 정보를 나타내고, Key는 검색 기준이 되며, Value는 실제 사용할 정보를 담고 있다.

Attention은 Query와 Key의 유사도를 계산하여 중요한 Value에 더 큰 가중치를 부여하고, 이를 이용해 최종 출력을 생성한다.

즉, **Attention의 핵심은 필요한 순간에 필요한 정보만 선택하여 사용하는 것**이라고 이해할 수 있다.
